# 领域资料

路线穿过草方格与滴灌带，风速和墒情来自不同监测设备；补给站的饮水容量需要按实际队伍占用。

## 观测与风险

- 每条观测携带设备侧采样时间 `observed_at`（带时区偏移的 ISO 8601）、读数 `value` 与质量标记 `quality_flag`（`good`/`suspect`/`bad`）。
- `source_record_id` 仅表示提交方对同一记录的识别符，与 `device_ref` 联合做幂等去重；示例文件不包含真实个人资料。
- 设备断联恢复后以 `is_backfill=true` 补报。服务端按采样时间的真实时刻（归一化 epoch 毫秒，跨时区偏移可比）排序处理，还原现场先后；迟到补报不会重开采样时刻更晚的、已处理过的风险。
- 只有**有效观测**（`good` 且读数在合理范围内）才参与路段风险判断：平均风速超过路段阈值（默认 10.8 m/s）或墒情低于阈值（默认 8%）即触发暂停，评估使用该时刻两类要素各自的最近有效读数。
- 同一路段同时只保留一个未解除风险（`open`/`confirmed`）；巡护可查看触发暂停的原始观测并人工复核（`confirm` 维持、`resolve` 解除），解除后再次越限可重新触发。

## 开放与补给

- 开放决定需给出预计队伍与人数；系统按人均水量（默认 2 升/人）从事先绑定的补给站原子扣减库存，库存不足或路段处于暂停中时拒绝开放。
- 每次预约必须携带 `idempotency_key`，同队伍同键的重复提交直接返回既有预约，不重复占用库存；取消预约归还水量。

## 角色与隐私

- `GATEWAY_TOKEN`（设备接入）、`RANGER_TOKEN`（巡护/调度）、`ECO_TOKEN`（生态调查）三种角色。
- 生态调查角色只能访问 `GET /v1/eco/segment-summary`，取得按路段与时间窗的脱敏聚合：不含设备编号、来源记录编号、原始读数、巡护人员与补给信息。
- 赛后分析不得使用游客数量推断植被影响。

运行时持久化文件由 `DATABASE_PATH` 决定；接口字段约定见 `contracts/entities.json`，交换示例见 `fixtures/example.json`。
