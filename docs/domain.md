# 领域资料

路线穿过草方格与滴灌带，风速和墒情来自不同监测设备；补给站的饮水容量需要按实际队伍占用。

`contracts/entities.json` 保存外部数据的交换字段与角色约定。来源编号（`source_ref`）仅表示提交方对同一记录的识别符，示例文件不包含真实个人资料。运行时持久化文件由 `DATABASE_PATH` 决定；时间字段使用带时区偏移的 ISO 8601 字符串。

## 观测接入

- 每条读数带 `observed_at`（观测时间）与 `quality`（valid / suspect / invalid）标记，服务端另记录 `received_at`。
- 设备断联恢复后可能补报或重发：按 `(device_ref, source_ref)` 去重，内容一致的重发返回原记录，内容不同的同键记录被拒绝（409）。
- 补报可能乱序到达，查询一律按 `observed_at` 还原先后，到达顺序只作次序平局时的参考。

## 路段风险与开放

- 只有 `quality = valid` 的观测参与风险判断：风速达到 `WIND_SPEED_LIMIT`（默认 14 m/s）或墒情低于 `SOIL_MOISTURE_MIN`（默认 8%）即生成风险事件，路段进入暂停。
- 同一路段已有未解除的事件时不重复生成；巡护人工复核可确认暂停（confirm_pause）或解除（release）。
- 开放检查结合路段风险状态与预计队伍所需水量：任一不满足即返回 hold 及原因。

## 补给库存

- 补给站按路段登记水容量；预约以 `request_ref` 为幂等键，重复提交返回原预约，不会重复占用库存。
- 预约在事务内校验剩余水量，不足即拒绝；取消预约立即释放库存。

## 数据可见性

- 巡护（ranger）可查看触发暂停的原始观测与全部复核记录。
- 生态调查（researcher）只能获取按日聚合的分段汇总（次数、风速均值/峰值、墒情均值/最低值），不含设备编号、来源标识与精确时刻，且只统计有效观测。
